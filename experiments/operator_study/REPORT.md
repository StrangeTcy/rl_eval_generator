# Observational-equivalence operator: offline validation

Question: does making a model run an observational-equivalence check before it infers a
hidden agent type or belief improve its reasoning about hidden states and beliefs.

**No model was contacted.** This sandbox has no container runtime, no provider credential
and no judge dependency, so a model result could only have been invented. What was run
instead is the instrument and the procedures, on matched generated instances, graded by the
environments' own oracles: every number below is what a reader that follows an arm's
procedure *exactly* scores, which bounds what the instruction can buy and shows where a
response format forbids the behavior the instruction asks for. It is not evidence that any
model's reasoning changed.

## What was fixed before anything was measured

Two overlays are declared in `envs/interventions.yaml` — `equivalence_check` (enumerate,
check identifiability, preserve the uncertainty) and `state_enumeration` (enumerate and
commit, no gate). Splitting them is the point: the two components predict different results,
and one id for both would score the combination and attribute it to neither.

The twins were generated and verified from `spec/observational-equivalence-check.yaml` with
`handoff/observational-equivalence-interventions.patch` applied: **39
members, 27 twin checks passed,
0 failed, 0
unverified.**

- 24 presentation twins: each differs from its baseline in bytes *and* keeps
  `pair_id` (basis latent_spec), so the two arms are the same task under different
  instructions — established on generated bytes before any answer source runs.
- 3 task-changing positive controls (`prior`): `pair_id` moves in all of them.
  Without that row the pair_id agreement above is unfalsified — an identity function that
  never separates anything also never fails to separate.
- Judge and scoring blocks are untouched; the instruction is appended to the shipped task
  render, which stays a byte-prefix of it.

## epistemic_games — where the question has a referent

This environment hides which world is actual and its answer format has a word for
underdetermination (`verdict: indistinguishable`, `most_supported: neither`). Compatible
states are enumerated from the behavior tables the agent is handed; an item is
non-identifiable when both worlds can produce the observed action with equal likelihood.

Reading, per stratum rather than pooled:

1. **Measurement 2 moves.** The control asserts a separation the instance forbids on
   100% of non-identifiable items.
   Enumerating the compatible states drops that to zero *with no permission to withhold*:
   the false-positive rate is not a confidence problem, it is a not-having-run-the-
   enumeration problem.
2. **Measurement 3 is where the shipped clause breaks.** `equivalence_check` buys its zero
   false positives with a
   50% under-commit rate: told to
   "preserve the uncertainty" it answers `neither` on the skewed-prior items, where the
   graded answer is a posterior of 0.6 and a support claim of world 1 — the prior is
   evidence, and an observation's silence does not cancel it. Accuracy
   0.500 against the control's
   0.000: real movement, half the available score.
3. **Scoping the clause to the evidence recovers the rest.** `equivalence_check_revised`
   reports `indistinguishable` about *the transcript* while still carrying the prior:
   accuracy 1.000,
   separations 0, over-commits 0, under-commits 0 — and identical numbers in the
   identifiable stratum, so nothing was traded away.
4. **The pooled row is reported as the trap it is.** Across both strata the shipped clause
   reads 0.833 against the
   revision's 1.000.
   An aggregate hides that its errors are all in one stratum and its successes in the other,
   which is exactly the misuse the question rules out.

## Recommendation

**Revise, within this scope.** Retain the enumeration half as the operator's content: it is
the semantics, it is what moves accuracy in all three environments, and it needs no new
vocabulary. Revise the uncertainty half to bind to the *evidence* rather than to the answer —
"report that this observation fails to separate the states, and keep whatever posterior the
prior and evidence jointly support" — because as written it costs half the scoreable cases in
the one environment where the failure it prevents actually exists, and costs the whole
submission in the two where the format has no value for it. Retain no claim about models from
this run: none was sampled.

Two conditions on the next step, in order:

1. Apply `handoff/observational-equivalence-interventions.patch` **between campaigns**. Case
   identity includes `config_sha256`, so an env-side edit re-plans every running campaign
   (here 496 → 532 cases, digest `4336d01b406572ba` → `71e41d42b6e2f42e`) and invalidates
   banked gate rows, which re-costs ~4.8 CPU-hours. The taxonomy and `spec/operators/` halves
   are committed here because they provably cannot move a plan; the test that pins that is
   `test_a_taxonomy_entry_alone_cannot_replan_a_campaign`.
2. Run the spec's arms against a model only after that, on the predeclared per-stratum
   estimators already in `tools/equivalence_check_study.py`, and add an arm that carries the
   enumeration instruction into a format *without* an underdetermined value — otherwise the
   model run reproduces the ambiguity this offline comparison separates.
