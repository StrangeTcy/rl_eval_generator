# Example interaction traces

This directory contains a reproducible, hand-authored demonstration script for
the stateful RoPE environment.

It is **not** a frontier-model transcript. The action sequence is selected by a
human to demonstrate the environment dynamics. The observations are produced by
`env_runner.py` and the environment tools when the script is run.

## Files

- `rope_hard_patch_offset_only.patch` — first plausible but incomplete repair.
- `rope_hard_patch_pairing.patch` — second repair, fixing adjacent-pair rotation.
- `rope_hard_patch_attention_cache.patch` — third repair, propagating offsets through cache and attention.
- `rope_hard_patch_frequency.patch` — final repair, fixing hard-mode frequency scaling.
- `rope_hard_solution.patch` — compact final patch with all fixes at once.
- `rope_hard_demo.sh` — regenerates the reference trace.
- `rope_hard_reference_human_trace.jsonl` — committed portable trace generated by the demo script.

## Run the demo

From the repository root:

```bash
bash examples/rope_hard_demo.sh
```

This writes:

```text
examples/rope_hard_reference_human_trace.jsonl
```

The committed trace is intentionally portable: it avoids PyTorch-dependent
commands so it can be regenerated in lightweight environments. It still shows a
staged investigation: extraction, section reading, partial repairs, further paper
inspection, and final patch application.

If PyTorch is available in the host environment, you can include the diagnostic
commands as well:

```bash
RUN_TORCH_DIAGNOSTICS=1 bash examples/rope_hard_demo.sh
```

That extended trace runs visible tests, train-like diagnostics, local eval, and
log inspection after the final patch.

## Intended trajectory

1. inspect sparse prompt;
2. discover tools;
3. inspect the buggy implementation;
4. extract paper text and observe missing/noisy sections;
5. inspect the section index and derivation;
6. apply an offset-only patch;
7. retry extraction until the appendix appears;
8. apply the adjacent-pair rotation patch;
9. apply the cache/attention offset propagation patch;
10. apply the frequency-scaling patch;
11. structurally verify that the final source contains all cross-file repairs.

The trace is a demonstration of environment mechanics and a reference solution
path, not a benchmark result for any particular model.
